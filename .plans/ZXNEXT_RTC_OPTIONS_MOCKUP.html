Why here, and what each row does

The Machine menu's own header comment reserves it for actions; set-once options (ROMs, the Z88's LCD) live on this page, shown only for the running machine. The Next's sound output is on both, because people switch it while they listen; nobody switches the clock's mode mid-session. The plan's first draft put a submenu under the Next's hardware items; the revised plan uses this page.

  1. The clock follows, a select (plan D1 nextRtcClock). Default: the host's clock (D2). Two choices, The host's clock and Emulated time: a select rather than a switch, because neither is "off".
  2. Keep between sessions, a switch (D1 nextRtcKeep). Default on (D2). Off: every start seeds from the host and the RAM is zero, today's behaviour.
  3. Kept clock, buttons (plan D8). Set to host time brings back the real time in either mode; Forget deletes the model's kept clock and zeroes its 56 bytes, and is enabled only while one exists (needsValue, like the ROM rows' Forget).

How it is wired (plan D1, D7):

• App settings, saved with the user's IDE settings like the sound output, not machine config saved with a project: a Settings row cannot read machine config, and the clock belongs to the user's machine.

• Live, no restart. The emulator panel pushes both settings into the running machine, as it does the sound output. Switching the mode never changes the time shown.
