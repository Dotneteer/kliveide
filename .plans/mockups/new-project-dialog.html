New Project — choosing among 41 machine models

The machine registry now has 10 machine types and 41 models, all in one dropdown. A project needs a machine type (it decides the templates and the build target) much more than an exact model, which the Machine type menu changes at any time and saves into the project. The proposal picks the type first, asks for a model only when the type has more than one, and turns the template list into cards that say what each one is.

Rules

  1. Type first. Tiles grouped into families. The Model field is always there; for a type with one model (Next, Scorpion) it shows that model, disabled, so the form never shifts.
  2. Model defaults to the running model if it is of that type, else the first Machine type menu favourite of that type, else the type's first model.
  3. Opens on the running machine, marked “Running”, so Create is one click for the common case.
  4. Templates follow the type, as cards: language, file type, one line on the toolchain. The current default stays selected.
  5. No templates, no tile. Commodore 64 has none today, so it is left out instead of offering an empty template list.

Keyboard

  • Arrow keys move between tiles (one radio group), Tab moves to Model, then the template cards.
  • Typing a letter on the tiles jumps to the next type starting with it.
  • Enter creates the project from anywhere once the form is valid.

What it needs

  • A family on each registry entry (or a small table) for the tile groups.
  • Template descriptions: a short template.json per template folder, falling back to the folder name.
  • NewProjectModel already splits machineId and modelId; only the view and view model change.
