Sprite space

1 · Two strips, each one line

  • One toolbar that never wraps: the view tabs, then only the active view's own control (the filter, or the pattern format). Palette, zoom, checker, raw bytes, the unused-slot format, the palette offset and Export as .spr move into ⋯ as the width drops, in that order.
  • The globals strip is one line. Raised flags (OFF, collision, too many) come first as chips, then Clip and Last visible; the rest sit behind +n more, which wraps the strip open in place.

2 · One list at a time until there is room for two

  • Sprites and Patterns are tabs. Both appears only when the document is wide enough for the table and four columns of patterns beside the rail (about 180ch); below that it is not offered, rather than offered and cramped.
  • The Patterns pane loses its inner toolbar, so the sheet starts right under its header.
  • Selecting in one view still marks the other: a sprite's pattern gets its marker when you switch tabs, and a pattern selects its first user in the table.

3 · The inspector is one column with two homes

  • Narrow: a band under the list, always visible, split in two: the sprite's details on the left (previews, the reason it may be hidden, the fields two to a line) and the sprite-space map on the right, sized to the band's height. A splitter trades list rows for band height; the size is remembered.
  • Medium and wide: a right rail, full height, 300-320px. Height is what the inspector needs (previews, fields, map stack vertically), and a side rail does not steal rows from the table.
  • The field table goes from three columns to two: the effective value, with the slot's own reading after it in the secondary hue when it differs (132 · own Δ+16). That removes the wrapped "SLOT BYTES SAY" header.

4 · The table scrolls as one piece

  • Header and rows live in the same scroller: the header is position: sticky; top: 0, so it moves sideways with the columns and stays put vertically.
  • The pinned pattern column holds only the thumbnail and the number (40, or 81 for a 4-bit pattern): 9ch instead of 14ch. Which half of the 256-byte slot a 4-bit pattern is moves to the scrolling fmt column (4·hi), and the cell's tooltip spells it out.
  • The first three columns (#, vis, pattern) are sticky to the left, so a row keeps its identity while you scroll to type or note. Each has a fixed width in ch (width = min = max, padding included), and each one's left offset is the sum of the widths before it, so none can shrink or slide under its neighbour.
  • In the app the rows are virtualized; the header renders as the scroller's first sticky child (the virtualizer's start margin is the header height). If the virtualizer cannot host it, the fallback is a separate header whose scrollLeft follows the body's.
