kliveide.net redesign · design review

Three directions for the Klive website

Each direction shows the landing page (with the language selector open) and a Get Started page with an annotated screenshot. The screenshots are dark, as decided. The IDE drawings are HTML stand-ins for the shots the Playwright recipes will capture.

What the current design gets wrong
It doesn't look like KliveThe landing page uses a generic Tailwind blue (#2563eb) and system font. The app's own palette (a cool neutral ramp and six accents) and the rainbow-stripe logo are missing.
Centered and genericA centered headline, two buttons and four equal text cards. That pattern fits any product, so nothing says "ZX Spectrum" until the screenshot.
Two sites, two looksThe landing page and the stock Nextra docs share no tokens, header or type. Clicking "Documentation" feels like leaving the site.
The screenshot does the work aloneOne small, old screenshot with no annotations. The unique features (BASIC debugging, reverse debugging, Next inspectors) never appear.

Recommended mix

A's tokens and type everywhere, so the site looks like the app. The landing page gets one loud moment from B: the stripe band across the hero and the four features in solid Spectrum colours. The docs screenshots use C's figure labels and numbered markers, and the numbered list under each one is page text, so it translates.

  • From A: neutrals, Sinclair Blue accent, header, type, docs layout.
  • From B: the hero stripe band and the colour feature blocks. Landing page only.
  • From C: "Fig." labels and numbered markers on screenshots.

A · Studio

The website uses the app's own design tokens: the same cool dark neutrals, the Sinclair Blue accent and a grotesk typeface. The logo's four stripes appear once, in the hero corner. It looks like a professional developer tool, the way VS Code or JetBrains sites do, and the screenshots blend in because they share the colours.

  • Lowest risk; the tokens already exist in theming/tokens/palette.ts.
  • The accent could follow a visitor-picked accent, like the app's View › Accent.
  • Docs keep Nextra's layout, re-skinned with the same tokens.

B · Spectrum Heritage

Black ground, the Spectrum's bright colours in solid blocks, the rainbow stripes running large across the hero, and a BASIC listing in a blue border as the first thing you read. Pixel-style labels mark the navigation. This one is the most memorable and appeals to nostalgia, but it puts the machine before the tool.

  • Strong identity and very shareable.
  • Hardest to keep readable in long docs, so the docs side stays calmer than the landing page.
  • Risk: reads as a games or retro site more than a serious IDE.

C · Field Manual

A light, technical-datasheet look: a fine grid, condensed uppercase headlines, monospaced labels, and numbered callouts drawn into the screenshots. It turns the "text never lives inside pixels" rule into the visual style itself, and it pairs naturally with the book. The dark screenshots stand out as framed figures on white.

  • Best fit for documentation-heavy pages and the annotated <Shot> component.
  • Needs a dark variant built from the same tokens.
  • Risk: quieter on first impression than B.

Why the mix

Build A as the system

Its tokens come straight from the app, so the site, the docs and the dark screenshots look like one product, and the light theme can be derived the way the app does it.

Borrow from B for the landing page only

Use the stripe band and the four solid feature blocks in the Spectrum colours as the landing page's one loud moment. The docs stay calm.

Borrow C's callouts for the docs

Numbered markers and monospaced figure labels make the annotated screenshots readable in every language.
