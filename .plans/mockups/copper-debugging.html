Mockup for .plans/COPPER_DEBUGGING_PLAN.md. It covers G3.1 (Copper list viewer), the Copper half of G3.8 (Copper breakpoints) and the proposed .copper pragma. The scene shows the C03 "staircase" list paused on cu:$00B. The values are illustrative, and the gutter, ruler ticks and Step Copper button respond to clicks.

3 · Writing the list with .copper

One pragma with sub-commands, like .dma, kept one-to-one with the hardware encoding. Hover decodes the emitted word. A .copper line matched to the live list has a source-level breakpoint, which becomes cu:$00B (D12). The errors are checked at assembly time.

asmprogram.asm
✕ Z0375 program.asm:34 Copper MOVE can write only NextRegs $00..$7F, not $8E

Sub-commands

.copper wait L, HLine 0..511, h 0..63 (paper x = 8·h). 1HHHHHHL LLLLLLLL
.copper move R, VNextReg $00..$7F, 8-bit value. 0RRRRRRR VVVVVVVV
.copper nop$00 $00
.copper halt$FF $FF, i.e. WAIT 511,63
.copper word XAny 16-bit word, big-endian

Source mapping

Each run of consecutive .copper lines is recorded in the debug info as a Copper block. The viewer matches the live RAM to blocks by shape (WAIT vs MOVE plus register), so values the CPU patches at runtime still map, and are flagged patched.

Parks, not warnings

Whether a WAIT can ever match depends on the timing (50/60 Hz, model), which the assembler cannot know. The viewer flags such WAITs instead, as for $013 above under 50 Hz.
