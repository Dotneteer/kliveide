HT-1080Z tape file viewers

Mockups for .cas, .cmd and .bas, on the TAP/TZX viewer's layout: a summary strip, a graphic of the whole file, the parts grouped by file, and the selected part's byte anatomy. Click a part, a timeline segment or a block on the memory map; hover a byte group to see its field. Every byte here is real: the demo BASIC program the Series II saved, and the default template's code assembled at $7000.

The .bas dilemma

A tokenised HT-1080Z program and a BASIC source file share the extension. They never share the content: Level II saves a tokenised .bas as an FFh byte followed by binary program lines (keywords are bytes 80h-FBh, line links and numbers are binary), while Klive BASIC, Boriel BASIC or a Level II listing saved as text are printable text. So the file itself can decide, wherever it is and whatever machine runs.

A. Decide by content recommended

A .bas that starts with FFh and holds non-text bytes is an HT-1080Z program: it opens in the HT viewer, gets Load and run in the Explorer, and goes into the deck. Any other .bas is source text: it opens in the code editor and builds as today. The file type registry gains an optional content test (the first bytes), checked when a file opens.

B. Decide by the project's machine

.bas is a tape in an HT-1080Z project and source text elsewhere. Simple, but wrong both ways: a Spectrum project can hold an HT program, and an HT project can hold a text listing.

C. A + run a text listing on the HT optional extra

On top of A: Load and run a text .bas on the HT by tokenising it with the ROM's own keyword table into a CLOAD tape, so a Level II listing typed in Klive's editor runs as it is. Text with no Level II syntax would only give ?SN ERRORs, so this is offered on the HT only.
