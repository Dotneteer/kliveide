ReferenceKlive BASICStandard library

Standard library

The standard library is a set of BASIC files that you include with #include <name.bas>. Klive BASIC provides the libraries documented for Boriel ZX BASIC, written as Klive’s own code, and Klive’s own farmem.bas.

#include <string.bas>
#include <hex.bas>
 
PRINT left("ZX Spectrum", 2); " "; hex16(49152)

This prints ZX C000.

How the compiler treats library files:

  • Only what you call is compiled. A library routine the program never calls adds nothing to it.
  • Names match in any case. LEFT, left and Left find the same routine, even in a case-sensitive program.
  • Library code is not yours. Warnings from it are not shown, and with Just My Code on (em-jmc), stepping goes over it.
  • Library options are their own. The libraries declare every variable and parameter with a type, so a program’s require-declarations, require-types or default_byref setting does not affect them.

The library files that Boriel ZX BASIC ships without documentation are not available. Calling a routine that Boriel’s documentation shows only as a listing to copy, and that no library here provides, gives an error saying so.

Text output

print42.bas

Text in 42 columns, with characters 6 pixels wide. print42 has its own cursor, separate from the cursors of PRINT and print64.

RoutineDescription
SUB print42(BYVAL s AS String)Prints a string at the print42 cursor in the permanent colours and moves the cursor on
SUB printat42(BYVAL y AS UByte, BYVAL x AS UByte)Moves the print42 cursor to row y (0-23) and column x (0-41)

print64.bas

Text in 64 columns, with characters 4 pixels wide. print64 has its own cursor, separate from the cursors of PRINT and print42.

RoutineDescription
SUB print64(BYVAL s AS String)Prints a string at the print64 cursor in the permanent colours and moves the cursor on
SUB printat64(BYVAL y AS UByte, BYVAL x AS UByte)Moves the print64 cursor to row y (0-23) and column x (0-63)

How print42 and print64 handle the cursor and control codes:

  • Text past the last column goes on at the next row, and text past the last row goes on at the top. The screen does not scroll.
  • In printat42 and printat64, a column past the last is the start of the next row, and a row past 23 is row 0.
  • CHR$ 13 starts a new line, and CHR$ 22 followed by a row and a column moves the cursor.
  • print42 prints characters 31-127 from the font and 144-164 from the user-defined graphics. CHR$ 8 steps back one place.
  • print64 prints characters 32-127.
  • Every other code, colour codes included, is skipped without moving the cursor.
  • The glyphs are Klive’s own. print42 narrows the machine’s font; print64 has its own 3 x 7 pixel font.

Input

input.bas

RoutineDescription
FUNCTION INPUT(BYVAL maxLength AS UByte) AS StringReads a line of at most maxLength characters at the PRINT position, with a flashing cursor, and returns it when ENTER is pressed

INPUT is a function, not Sinclair BASIC’s INPUT statement. Use PRINT AT to place the cursor first. DELETE (CAPS SHIFT + 0) removes the last character.

input42.bas

RoutineDescription
FUNCTION INPUT42(BYVAL maxChars AS UInteger) AS StringReads a line of at most maxChars characters at the print42 cursor, echoed through print42, and returns it when ENTER is pressed

Screen

attr.bas

RoutineDescription
FUNCTION ATTR(BYVAL row AS UByte, BYVAL col AS UByte) AS UByteThe attribute byte of the character cell at row, col; all 24 rows can be read

point.bas

RoutineDescription
FUNCTION POINT(BYVAL x AS UByte, BYVAL y AS UByte) AS Byte1 when the pixel at x, y is set, 0 when it is not, and -1 for a y past the top

POINT counts as PLOT does: (0, 0) is the bottom-left pixel and all 192 rows can be tested. With the sinclair-compatible option it takes the ROM’s coordinates instead: y counts the 176 rows above the editor area, so POINT(x, y) tests the pixel that PLOT x, y + 16 sets.

screen.bas

RoutineDescription
FUNCTION SCREEN$(BYVAL row AS UByte, BYVAL col AS UByte) AS StringThe character shown at row, col, when it is one of the font’s characters 32-127, normal or inverse; otherwise the empty string. All 24 rows can be read

sinclair.bas

Includes ATTR, POINT and SCREEN$ together. The sinclair-compatible header option includes it automatically, before the program’s first line.

pos.bas and csrlin.bas

RoutineLibraryDescription
FUNCTION POS() AS UBytepos.basThe column of the PRINT cursor: 0 at the left, 32 when the line is full
FUNCTION CSRLIN() AS UBytecsrlin.basThe row of the PRINT cursor: 0 at the top, 23 at the bottom (24 after a new line on row 23, until the screen scrolls)

Keyboard

keys.bas

Reads the keyboard through port $FE, without the ROM.

RoutineDescription
FUNCTION GetKey() AS UByteWaits for a key and returns its character code
FUNCTION GetKeyScanCode() AS UIntegerThe scan code of the keys held down in the first half-row that has any, their bits combined; 0 when no key is down. Does not wait
FUNCTION MultiKeys(BYVAL scanCode AS UInteger) AS UByteTests the keys of the given scan codes, combined with bOR; returns the bits of the keys that are down, or 0

The library defines a UInteger constant for the scan code of every key: KEYA to KEYZ, KEY0 to KEY9, KEYSPACE, KEYENTER, KEYSYMBOL and KEYCAPS. The high byte selects the key’s half-row and the low byte is its bit there. Only codes of the same half-row can be combined.

#include <keys.bas>
PRINT "Press P or O"
DO
  PAUSE 1
LOOP UNTIL MultiKeys(KEYP BOR KEYO) <> 0

Strings and numbers

string.bas

RoutineDescription
FUNCTION left(BYVAL s AS String, BYVAL n AS UInteger) AS StringThe first n characters of s; all of s when it is shorter
FUNCTION right(BYVAL s AS String, BYVAL n AS UInteger) AS StringThe last n characters of s; the empty string when s is shorter
FUNCTION mid(BYVAL s AS String, BYVAL start AS UInteger, BYVAL n AS UInteger) AS StringUp to n characters of s from position start; the empty string when start is past the end

mid counts start from 0, whatever the string base.

asc.bas

RoutineDescription
FUNCTION asc(BYVAL s AS String, BYVAL n AS UInteger) AS UByteThe code of the n-th character of s, counted from the string base; 0 past the end

hex.bas

RoutineDescription
FUNCTION hex(BYVAL n AS ULong) AS String8 hexadecimal digits of a 32-bit value
FUNCTION hex16(BYVAL n AS UInteger) AS String4 hexadecimal digits of a 16-bit value
FUNCTION hex8(BYVAL n AS UByte) AS String2 hexadecimal digits of an 8-bit value

The digits are upper case, with leading zeros.

fmath.bas

Fast trigonometry in Fixed arithmetic, with angles in degrees and results accurate to about 0.25%.

RoutineDescription
FUNCTION fSin(BYVAL num AS Fixed) AS FixedThe sine of an angle in degrees
FUNCTION fCos(BYVAL num AS Fixed) AS FixedThe cosine, computed as fSin(90 - num)
FUNCTION fTan(BYVAL num AS Fixed) AS FixedThe tangent, computed as fSin(num) / fSin(90 - num)

An angle outside 0-360 is reduced with MOD 360 first.

hmirror.bas

RoutineDescription
FUNCTION FASTCALL hMirror(BYVAL number AS UByte) AS UByteThe byte with its bit order reversed: bit 7 becomes bit 0. Useful for mirroring sprite graphics

Memory

memorybank.bas

For the ZX Spectrum 128K and compatible models. The bank at $C000 is selected through port $7FFD, and the system variable BANKM keeps the last value written there.

RoutineDescription
SUB SetBank(BYVAL bankNumber AS UByte)Pages RAM bank 0-7 into $C000-$FFFF and records it in BANKM
FUNCTION GetBank() AS UByteThe RAM bank at $C000, read from BANKM
SUB SetCodeBank(BYVAL bankNumber AS UByte)Copies a RAM bank to $8000-$BFFF: the bank is paged in at $C000, copied, and the bank that was there before is paged back

A program that extends past $C000 can break when another bank is paged in there.

farmem.bas

For CODEBANK programs on the ZX Spectrum Next. These routines read and write bank-local data through FARPTR values, from resident or banked code, without changing the current bank. A FARPTR value is a ULong with the bank in bits 16-23 and the address in bits 0-15; bank 0 is resident memory.

RoutineDescription
FUNCTION FarPeek(BYVAL fp AS ULong) AS UByteThe byte at a FARPTR
FUNCTION FASTCALL FarPeekW(BYVAL fp AS ULong) AS UIntegerThe word at a FARPTR
SUB FarPoke(BYVAL fp AS ULong, BYVAL v AS UByte)Writes a byte at a FARPTR
SUB FarPokeW(BYVAL fp AS ULong, BYVAL v AS UInteger)Writes a word at a FARPTR
SUB FarCopy(BYVAL fp AS ULong, BYVAL dest AS UInteger, BYVAL count AS UInteger)Copies count bytes from a bank to resident memory at dest
SUB FarCopyTo(BYVAL fp AS ULong, BYVAL src AS UInteger, BYVAL count AS UInteger)Copies count bytes from resident memory at src into a bank
FUNCTION FASTCALL FarStr(BYVAL fp AS ULong) AS StringA string read from a bank, where the data at fp is a 2-byte length followed by the characters. The empty string when the heap is full
  • Include farmem.bas outside CODEBANK blocks: it must stay resident.
  • The resident address of FarCopy and FarCopyTo must not be in the CODEBANK window, and an access must not run past the window’s end.
  • The routines must not be called from an interrupt handler.

Decompression

zx0.bas

Decompresses data packed with Einar Saukas’ ZX0  compressor, in its current format (version 2). Every routine has the same parameters: src is the address of the packed data and dst the destination.

RoutineDescription
SUB FASTCALL dzx0Standard(BYVAL src AS UInteger, BYVAL dst AS UInteger)The smallest decoder
SUB FASTCALL dzx0Turbo(BYVAL src AS UInteger, BYVAL dst AS UInteger)A faster decoder
SUB FASTCALL dzx0Mega(BYVAL src AS UInteger, BYVAL dst AS UInteger)The fastest decoder
SUB FASTCALL dzx0StandardBack(BYVAL src AS UInteger, BYVAL dst AS UInteger)dzx0Standard for data packed backwards
SUB FASTCALL dzx0TurboBack(BYVAL src AS UInteger, BYVAL dst AS UInteger)dzx0Turbo for data packed backwards
SUB FASTCALL dzx0MegaBack(BYVAL src AS UInteger, BYVAL dst AS UInteger)dzx0Mega for data packed backwards
SUB FASTCALL dzx0SmartRCS(BYVAL src AS UInteger, BYVAL dst AS UInteger)A small decoder for RCS-encoded screens
SUB FASTCALL dzx0SmartRCSBack(BYVAL src AS UInteger, BYVAL dst AS UInteger)dzx0SmartRCS for data packed backwards
SUB FASTCALL dzx0AgileRCS(BYVAL src AS UInteger, BYVAL dst AS UInteger)A faster decoder for RCS-encoded screens
  • All the routines decode the same format; the variants differ in size and speed.
  • The Back routines read data made by the compressor’s backwards mode. Their src and dst are the addresses of the last byte of the packed data and of the destination.
  • The RCS routines write the bytes that land in the screen bitmap (16384-22527) to their RCS places, and every other byte as it is.

ZX0’s author asks that programs that use it mention ZX0 in their documentation.
