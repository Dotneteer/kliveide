# The Memory View

The **Memory** view shows the machine's memory as a hex dump with characters beside it. Use it to
check what your program wrote, to look into a bank that is not paged in, to change a byte while the
machine is paused, and, with code coverage on, to see which bytes were executed, read or written.

<Shot
  src="guides/debugging/memory/memory-view.webp"
  alt="The Memory view with its toolbar: Decimal, View, Chars, Bank, Heat, Go To and Show as graphics"
  caption="The Memory view and its toolbar."
  width={760}
/>

## Open it

Choose **View › Machine Views › Memory**, or click **Show Memory Panel** on the IDE toolbar. The
view opens as a document in the IDE; the same items close it again.

## The toolbar

- **Decimal**: show addresses and bytes in decimal instead of hexadecimal (off by default).
- **View**: the layout: **8B / 1 col** (8 bytes a row), **8B / 2 col** (two 8-byte sections side by
  side, the default) or **16B / 1 col**.
- **Chars**: show each byte's character beside the dump (on by default). Hovering a byte outlines
  its character.
- **Bank**: show the bank label in front of each address (on by default; only on machines that
  page memory).
- **Heat**: colour the bytes by how they were used since coverage started: **Executed**, **Read**,
  **Written** or **All**, or **Off**. It appears on machines that record coverage; turn coverage on
  with **Debug › Code Coverage**. See [Code coverage and the heat map](/en/guides/analysis/code-coverage/).
- **Go To**: type an address and press <kbd>Enter</kbd>. The view scrolls there and the byte at that
  address flashes for a few seconds. Type decimal in decimal mode, hexadecimal otherwise.
- **Show as graphics**: open the [Graphics Finder](/en/guides/analysis/graphics-finder/) at the
  address at the top of the view, to look for sprites and fonts.

Hover a byte to see its value in hexadecimal, decimal and binary.

## Look at one bank

On machines that page memory, a second toolbar row has a **64K View** switch. On (the default), the
view shows the 64K the CPU sees now, with the current paging. Off, choose a ROM page or RAM bank in
the **Selected bank** chooser: the view shows that partition even when it is not paged in. The
partition names are listed [below](#machine-specific-memory-partitions).

## Change a byte

<Steps>

### Right-click the byte

Right-click a RAM byte in the dump. The **Set Memory Content** dialog opens for that address.

### Enter the value

Type a decimal number, a hexadecimal one with `$`, or a binary one with `%`; spaces between digits
are ignored. Choose the **Content size**, 1 to 4 bytes. The value is written least significant
byte first; tick **Big-endian write** to write the most significant byte first.

### Click Set

Click **Set** or press <kbd>Enter</kbd>. A ROM address cannot be written; the dialog says so.

</Steps>

<Callout type="info">
Memory can be written while the machine runs, but the program may overwrite the value at once:
pause it first. Writing also works while the machine is stopped, which is useful on machines whose
memory survives switching off, such as the Cambridge Z88. While you stand in the past with reverse
debugging on, an edit asks to [take over](/en/guides/debugging/reverse-debugging/#taking-over) first.
</Callout>

## Machine-specific memory partitions

Every partition has one **name** and one **description**. The name is what identifies it: it is what
the bank column shows, what a breakpoint is listed under, and what the `bp-*` commands accept in a
partition-qualified address such as `bp-set r1:$32ac`. The description is the longer form a chooser
spells out beside the name; it is never typed and never appears in a breakpoint key.

Names are accepted case-insensitively, so `r1` and `R1` are the same partition.

### ZX Spectrum 48K

No partitions: this model supports only the 64K view.

### ZX Spectrum 128K

| Name | Description | What it is |
| --- | --- | --- |
| `R0`, `R1` | ROM 0, ROM 1 | The two ROM pages, 16K each |
| `B0` ... `B7` | Bank 0 ... Bank 7 | The eight RAM banks, 16K each |

### ZX Spectrum +2E, +3E

| Name | Description | What it is |
| --- | --- | --- |
| `R0` ... `R3` | ROM 0 ... ROM 3 | The four ROM pages, 16K each |
| `B0` ... `B7` | Bank 0 ... Bank 7 | The eight RAM banks, 16K each |

### Cambridge Z88

| Name | Description | What it is |
| --- | --- | --- |
| `00` ... `FF` | Bank $00 ... Bank $FF | The 256 banks, 16K each |

The Z88 has no ROM partitions: its ROM is a card in slot 0 rather than a fixed page.

### ZX Spectrum Next

| Group | Name | What it is |
| --- | --- | --- |
| Next ROM | `R0` ... `R3` | The ROM pages of the ZX Next OS, 16K each |
| Alt ROM | `X0`, `X1` | The alternate ROM pages, 16K each |
| DivMMC ROM | `DM` | The DivMMC ROM, 8K |
| DivMMC RAM | `M0` ... `MF` | The 16 DivMMC RAM banks, 8K each |
| &mdash; | `00` ... `DF` | The 224 RAM pages, 8K each (`000` to `223` in decimal view) |

The bank chooser heads each group once rather than repeating it on every entry, so a DivMMC RAM
bank appears as `M3` under a **DivMMC RAM** heading. Hovering any entry names it in full.

<Callout type="info">
On the ZX Next a RAM partition is an **8K page**, which is the granularity of the machine's own MMU.
Code and tools that think in 16K banks (the `.bank` pragma, a NEX file's banks, the
`.nex` viewer) address them in pairs: 16K bank *B* is the two partitions `2B` and `2B+1`, its
low half first. So 16K bank 5 is partitions `0A` and `0B`.
</Callout>

<Callout type="info">
The alternate ROMs are named `X0` and `X1` rather than the more obvious `A0`/`A1`, and the DivMMC
RAM banks `M0`...`MF` rather than `D0`...`DF`, because `A0` and `D0` are already valid *RAM bank*
names on this machine. A name has to mean one thing.

Earlier versions called the alternate ROMs `Q0` and `Q1`. Those spellings are still accepted by
`bp-set` and friends, so existing scripts keep working, but the IDE now shows `X0` and `X1`.
</Callout>
