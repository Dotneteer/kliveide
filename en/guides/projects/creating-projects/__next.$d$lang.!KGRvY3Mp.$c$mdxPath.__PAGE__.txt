# Creating a project

A *Klive project* is a folder that holds your source files together with a `klive.project` file and a
`build.ksx` build script. Create one when you want to write a program: the project remembers the
machine it targets, its build root and your breakpoints, and gives you one-click Compile, Run and
Debug.

## Create a project

<Steps>

### Open the dialog

Choose **File › New Project...**, or click **Create a Klive Project** in the empty Explorer. The
**Create a new Klive project** dialog opens.

<Shot
  src="get-started/new-project.webp"
  alt="The Create a new Klive project dialog with a ZX Spectrum 48K machine type and the default template"
  caption="The Create a new Klive project dialog"
  width={620}
/>

### Choose the machine and model

Pick the **Machine type**. The list is grouped into **ZX Spectrum** (48K, 128K, +2E/+3E, Next),
**Spectrum compatibles** (Timex, Scorpion) and **Other Z80 machines** (ZX81, ZX80, Cambridge Z88,
HT-1080Z). When the machine has more than one model, choose it under **Model**: the dialog starts on
the model that is running now, or else on your favourite model of that machine.

### Choose a template

Pick a **Project Template**. The list shows the templates of the chosen machine; `default` is a Klive
Z80 assembly project. [Project templates](/en/guides/projects/project-templates/) lists them all.

### Name the project

Type a **Project name**. **Project folder** is optional: the project is created as a subfolder of
it, or of the `KliveProjects` folder in your home folder when you leave it empty.

### Create it

Click **Create**. Klive creates the folder, opens it and switches the emulator to the project's
machine and model.

</Steps>

You can also create a project from the [command prompt](/en/guides/editing/command-prompt/) with
[`newp`](/en/reference/commands#newp), for example `newp sp48 MyGame default -o`.

To open an existing project, choose **File › Open Folder...** or **File › Open Recent**. A folder
without a valid `klive.project` file opens too, but as a plain folder: no build root, no build bar,
no Build menu.

## What a project contains

A new project from the `default` template on the ZX Spectrum 48K looks like this:

```
MyGame/
├─ code/
│  └─ code.kz80.asm   the build root
├─ build.ksx          the build functions
└─ klive.project      the project's settings
```

<Shot
  src="guides/projects/creating-projects/explorer-build-root.webp"
  alt="The Project Explorer of a new ZX Spectrum 48K project, with the build root marked"
  caption="A new project in the Project Explorer; the marker after code.kz80.asm shows the build root"
  width={420}
/>

- **`klive.project`** stores the project's machine and model, its build root, breakpoints, project
  settings and IDE state. Klive updates it while you work. It opens read-only in the editor.
- **`build.ksx`** holds the functions behind Compile, Inject, Run, Debug and Export, and any build
  commands you add. See [The build system](/en/guides/projects/build-system/).
- **The source files** of the template.

In the Project Explorer, a home icon in front of the root folder's name means the folder is a Klive
project.

<Callout type="warning">
Do not edit `klive.project` while the project is open in Klive: Klive writes the file itself and
overwrites your changes. If Klive cannot read the file when it opens the folder, the folder opens as
a plain folder.
</Callout>

## The build root

The *build root* is the main source file, the one Klive compiles; the files it includes are compiled
with it. A project has one build root, which the template sets. The Explorer marks it with a build
icon after the file name.

To make another file the build root, right-click it in the Explorer and choose **Promote to Build
Root**. The command appears only for source files (see
[File types](/en/guides/projects/file-types/)). **Demote from Build Root** on the current build root
leaves the project without one. Renaming the build root keeps it the build root.

## Build, run and debug from the build bar

When the build root is the active document, the build bar appears at the right end of the document
tab bar:

<Shot
  src="guides/projects/creating-projects/build-bar.webp"
  alt="The build buttons at the right of the document tab bar"
  caption="The build bar over the build root"
  width={520}
/>

| Button (tooltip) | `build.ksx` function | What it does |
| --- | --- | --- |
| **Compile code** | `buildCode` | Compiles the build root. Errors go to the Build output and the editor. |
| **Inject code into the virtual machine** | `injectCode` | Compiles, then writes the code into the paused machine's memory. You resume the machine and start the code yourself, for example with `RANDOMIZE USR 32768`. Not shown on the ZX Spectrum Next, which loads a `.nex` file instead. |
| **Inject code and start the virtual machine** | `runCode` | Compiles, restarts the machine, injects the code and runs it. |
| **Inject code and start debugging** | `debugCode` | The same, in a debug session: breakpoints stop the program. See [Running and debugging](/en/guides/debugging/run-debug/). |
| **Show script output** | – | Opens the output of the last build function the bar ran, as a document. |

The buttons are disabled while a compile is running. Each one runs a function of `build.ksx`, so you
can change what a button does by editing that function. The same functions, with **Export code...**,
are in the **Build** menu.

When you run or debug, Klive compiles the code (and stops if it fails), restarts the machine and
lets its ROM reach a point where starting a program is safe, typing keys for it where needed. Then it
pauses the machine, injects the code, sets the program counter to the entry point and resumes.

<Callout type="info">
Projects created before Klive v0.32.0 have no `build.ksx`, and the build bar does nothing for them.
[The build system](/en/guides/projects/build-system/#the-default-build-file) shows the file to add.
</Callout>
