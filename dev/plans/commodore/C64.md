## 3. Time base and memory (D6; C64 §2, §10)
- **Master tick = one φ0 cycle**, executed as φ1 (the VIC's fetch, 8 pixels, the border/raster/sprite
  checks) then φ2 (the CPU's access, or the VIC's c/s-access when BA is low and AEC has passed its 3-cycle
  delay). The CIAs and the SID clock once per tick; the drive runs from the rational accumulator after it
  (DRIVE_1541.md §5).
- **The frame** starts at raster line 0 cycle 1 (VICE's convention, so oracle comparisons line up); a
  frame is `cyclesPerLine × lines` ticks per model.
- **PLA:** LORAM/HIRAM/CHAREN from the CPU port, GAME/EXROM from the cartridge; a 32-entry table → a
  per-4K-page map for reads, writes and the VIC's view, rebuilt on any input change. Ultimax holes and
  the VIC's Ultimax view (C64 OQ6, VIC-II §8).
- **Open bus** returns the VIC's last φ1 byte (unmapped Ultimax areas, $DE00–$DFFF without a cartridge);
  colour RAM's upper nibble comes from the same bus (VICE and MAME disagree on details, C64 §11: one
  constant).
- **RAM power-on pattern:** a per-model pattern constant (C64 OQ5), deterministic.
- **The $00/$01 write quirk** (the RAM below receives the VIC's φ1 byte) through the CPU core's port hook
  (CPU §1.4).

## 4. The VIC-II (Phases 3–4; VIC-II §2–§9)
- **Cycle tables as data**, one per line length (63, 64, 65), each cycle: φ1 access (c, g, p, s, r, i),
  φ2 access, BA contribution, X position, and the check flags (VC/RC update, sprite DMA, expansion,
  display, crunch, MCBASE, border left/right). Written from Bauer's diagrams (`dev/research/vic-ii.txt`) and
  VIC-II §2 by `vic2-cycles-gen.cjs`, never copied from an emulator; the disagreements (VIC-II §13: NTSC
  sprite cycles, MCBASE/crunch, VCBASE reset) are flags in the description with the chosen default.
- **State:** VC, VCBASE, RC, VMLI, display/idle state, the two border flip-flops, sprite MC/MCBASE/expansion
  flip-flops, collision latches, the raster IRQ edge, the light-pen latch (once per frame, also from CIA1).
- **Badlines and BA:** BA low 3 cycles before the c-accesses; the CPU core's RDY holds only read cycles
  (CPU §4); the 3-cycle write window falls out of that.
- **Pixels:** 8 colour indices per tick into a line buffer covering the model's full X range; a register
  write lands at the pixel the revision flags say (VIC-II §1.4, OQ12). A separate **palette stage** maps
  indices to RGB (D15: Klive's own palettes per luma set, VIC-II §7), with an optional PAL delay-line blend.
- **TV window:** the visible area per model as constants (VIC-II §1); `getBeamPosition` and
  `BEAM_POSITION_MACHINE_IDS`.
- **Proof:** `test/c64-hw/vic2/` per-feature tests on the bare machine (Klive test ROM), then the VICE
  testprogs `VICII/` folder run by the driver (D16), the pass list recorded in the core README; demo
  effects (FLI, FLD, VSP, open borders, sprite stretching, linecrunch) checked by eye and pinned by hash.

## 5. CIAs and input (Phase 5; C64 §3–§4)
- `cia6526.c` (shared with the C128): timers A/B with all start/one-shot/load/count modes and the
  documented pipeline delays, the old/new ICR timing (one constant from the profile), the timer B quirk
  as an option (C64 §11 disagreement), TOD at 50/60 Hz from a mains-tick input (C64 OQ3 answered by
  running the ROM), the serial shift register, ports with the keyboard/joystick wiring.
- CIA1: keyboard matrix (with ghosting as the hardware produces it), joysticks 1/2, paddles through the
  SID POT lines (CIA1 selects the pair), the FLAG pin from the Datasette. CIA2: VIC bank, IEC lines, user
  port, NMI. RESTORE → NMI through its one-shot.
- Host input: `C64KeyMappings.ts` (positional and symbolic layouts), joystick through Klive's joystick
  input, paddles and the 1351 through the pointer capture the Next's mouse uses (generalised in its own
  commit if it is Next-only).
- **Proof:** Lorenz's suite (needs the KERNAL; local tier) for the CPU and CIA; the CIA testprogs; keyboard
  matrix tests; the virtual keyboard (after its design is approved, drawn from a photograph, colours as
  tokens; an entry in `dev/ai/ui-theming-intent-and-lessons.md`).

## 6. The SID (Phase 5; D9; SID §1–§6)
### 6.1 Digital part — exact in every mode
Three voices: 24-bit accumulators, waveforms, the 23-bit noise LFSR with writeback and lock-up, test bit,
sync and ring; the ADSR with its 15-bit rate counter (never reset; the delay bug), the exponential counter,
one-cycle pipelines; OSC3/ENV3; the read-back fade of write-only registers (6581 vs 8580 constants); the
8580's one-cycle write delay; POTX/POTY on the 512-cycle cycle (SID §1–§3, §5). Clocked once per φ2 tick.

### 6.2 Analog part — separable, staged
- Stage A: combined waveforms from Klive's own model (SID §2: not a plain AND; the parameters fitted by
  Klive's measurement or analysis, SID OQ2/OQ5), DACs with the 6581's non-linearity as a table, a linear
  state-variable filter, the board's external filter, the DC offsets that make `$D418` digis audible on the
  6581, band-limiting to the host rate (a polyphase FIR or biquad-then-decimate, SID §6.1).
- Stage B: the 6581's non-linear filter model, written from published circuit analyses (SID §4), behind a
  quality setting.
- The analog path may run at reduced rate or be skipped when audio is muted (turbo, headless) — the
  digital state is unaffected (SID OQ11). Host settings never reach a non-volatile static (trap T9a): the
  quality switch selects code, not state that enters keyframes.

### 6.3 Mixing
SID and Datasette clicks into `common/wasm/audio-channels.c` (`KLIVE_AUDIO_CHANNELS`), with taps for the
audio mixer.

### 6.4 Proof
- Digital: Klive test programs reading OSC3/ENV3 and the bus fade on the C64, compared cycle by cycle with
  the same program on VICE x64sc (oracle, recorded); noise-writeback and ADSR-bug programs.
- Analog: Klive-written register sequences rendered by Klive and by sidplayfp (oracle); RMS and spectral
  tolerances fixed in Phase 5 after the first measurement and then pinned; by ear on a few HVSC tunes the
  developer owns (HVSC is never committed, SID OQ7).
- Cost: `benchmark:c64-wasm` with stage A and B; the default quality is the best one above the 10× gate
  (SID OQ1).

## 7. Tape (Phase 7; C64 §6)
`cbm-tape.c`: TAP v0/v1 pulses to CIA1 FLAG, the sense and motor lines on the CPU port, recording from the
write line into TAP; a play turbo while the motor runs (the TVC pattern). PRG-to-TAP export writes the
KERNAL's standard format (pulse timings from C64 §6; the disagreement on pulse durations decided by
reading back on Klive's own core and on VICE). The SX-64 and C64GS profiles have no Datasette.

## 8. Cartridges (Phase 7; C64 §5)
`CrtFile.ts` parses CRT (header, CHIP packets, hardware type) and raw 8K/16K binaries; `c64-cart.c`
implements, first: normal 8K/16K, Ultimax, Ocean, Fun Play, System 3 (C64 OQ8), Magic Desk, EasyFlash
(read; writing is a follow-up), Action Replay/Retro Replay basics (freeze through NMI). The expansion port
exposes GAME/EXROM/IO1/IO2/NMI/IRQ/RESET and a **DMA/BA request** so the REU can come later (C64 OQ7).

## 9. Tests (beyond §4–§8)
- Harness `test/harness/c64/`: `bootToBasic(model)` (the READY key wait found by running the ROM, observed
  by the stack and the keyboard buffer), `typeText`, `runFrames`, `runTo`, `step`, `peek`/`poke` (CPU view
  and RAM), `vic()`, `cia(n)`, `sid()`, a bare machine with the Klive test ROM.
- `test/c64-hw/`: memory (every PLA configuration, Ultimax, open bus, colour RAM), vic2, cia, sid, input,
  tape, cart, models (each profile boots or, without ROMs, runs the test ROM).
- External: Lorenz (local tier), VICE testprogs `VICII/`, `CIA/`, `SID/`, `general/` (fetched; pass lists in
  the README, Phase 0 records VICE x64sc's own pass list as the reference).
- Cross-core suites (CPU_NEUTRAL_DEBUGGING.md §5).
- Benchmark: > 10× real time with a 1541 attached, analog SID stage A.
