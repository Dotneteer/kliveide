# The C128 core

Part of `COMMODORE_PLAN.md` (milestone M4, Phase 11). Research: `C128.md` (C128 §n), `C64_VIC_II.md`,
`DRIVE_1541.md` §5. The last machine because it needs everything before it: the C64's chips, the drive,
**two CPUs in one machine** and a second video chip on its own clock.

## 2. Models (C128 §1)
`c128-pal` (default), `c128-ntsc`, `c128d-pal` (internal 1571), `c128dcr-pal`, `c128dcr-ntsc` (8568 VDC,
64K VDC RAM). Profile fields: VIC-IIe 8564/8566 (VIC-II OQ5: whether they behave like 856x C64 chips), VDC
version, VDC RAM, SID/CIA types (C128 OQ4), ROM set (four 16K chips or two 32K, national character ROMs,
C128 OQ5).

## 3. Clocks and the two CPUs (C128 §2–§3; decision D8)
- **Master tick = half a φ0 cycle.** In 1 MHz mode the 8502 uses one half, the VIC-IIe the other, as on
  the C64. In 2 MHz mode (`$D030` bit 0) the 8502 uses both halves and the VIC display breaks (C128 OQ2,
  VIC-II OQ7: the behaviour is recorded from VICE runs and constants).
- **The Z80** gets two T-states per φ0 cycle, in the half the VIC does not use; one T-state = half a 1 MHz
  cycle (2.045 MHz NTSC, 1.970 MHz PAL). No wait states on memory or I/O; VIC BA stalls it (C128 §2,
  OQ1: the stall granularity is a constant, M-cycle by default).
- **Klive's `z80.c` is reused unchanged:** the C128 TU defines its `Z80_*` hooks (memory and I/O through
  the MMU/PLA funnel with the Z80's I/O cycles flagged, `Z80_TACT_PLUS_N` advancing the master tick
  without contention, IM 1, NMI unconnected) before the include, as every Z80 core does. No new hook is
  expected; one that is needed goes in under `#ifdef`, with every Z80 core byte-identical (the TVC's H1
  rule).
- **CPU switch:** MMU `$D505` bit 0 = 0 at power-on, so the **Z80 runs first** (its ROM at $0000 is a 4K
  slice of the KERNAL chip), sets up the MMU and writes `$B1` to hand over. Neither CPU is reset by a
  switch: each freezes and resumes (C128 §3; switch duration C128 OQ3 from VICE runs).
- **Interrupts:** IRQ to both CPUs, NMI to the 8502 only (C128 OQ6 for the Z80's mode at run time).
- **Debugging:** the descriptor lists `z80`, `m8502`, `drive8`; the debug target follows the active CPU
  unless pinned; a step over the MMU write that switches CPUs ends on the other CPU
  (CPU_NEUTRAL_DEBUGGING.md §4). The Z80 keeps its own panel, disassembler and conditions; the 8502 its own.
- "Boot straight into the 8502" is a convenience option, not the default (C128 §10 item 5).

## 4. MMU, memory, C64 mode (C128 §4, §7)
MMU registers $D500–$D50B and the LCR mirror at $FF00–$FF04, configuration and pre-configuration
registers, RAM banks 0/1 (2/3 noted), common RAM top/bottom, page 0/1 relocation, the 40/80 key and
GAME/EXROM sensing, the one-way C64-mode switch (which then runs the C64 memory map with the C64 ROMs in
the C128's chips), the version register (C128 OQ9). Memory partitions in the IDE: RAM 0/1, ROMs, the VDC's
RAM as its own space.

## 5. The VDC (C128 §5)
- Its own 16 MHz clock domain, free-running against φ0: stepped per character clock in **catch-up** to the
  current master tick on every $D600/$D601 access and at frame end (C128 §10 item 3). The ready bit's latency
  follows that model (C128 OQ10).
- 37 registers, the per-line fetch order measured by logic analyser (C128 §5), attribute and bitmap modes,
  block copy/fill, interlace, 16K/64K layout (R28 bit 4), the version in status bits 2–0, R37 on the 8568
  only, RGBI output.
- **Two screens:** the emulator shows the VIC-IIe or the VDC by the 40/80 key state, or both side by side
  (an emulator-window option); each its own canvas and beam position.
- MAME's `mos8563.cpp` (BSD-3) may be ported in named pieces (D1).

## 6. Keyboard, the 1571, burst mode (C128 §6, §8; DRIVE §5)
- The extended matrix (extra rows through VIC-IIe `$D02F`, CAPS LOCK on the 8502 port bit 6, 40/80,
  the keypad).
- **The 1571:** the 1541 drive core at 1 or 2 MHz, the GCR path shared, a WD1770 (the shared `wd1793.c`'s
  1770 variant, sector level, DRIVE OQ10) for MFM, a CIA for burst; D71/G71 images (DRIVE OQ11). The
  C128D profile has it built in.
- **Burst (fast serial):** the C128's CIA1 serial register and SRQ against the 1571's CIA, the handshake
  recorded from VICE runs (DRIVE OQ8).

## 7. Run, CP/M, tests
- Run in C128 mode: BASIC start $1C01 (C128 OQ14: pointers after LOAD), inject after READY, `RUN` through the
  keyboard buffer (C128 OQ13). In C64 mode: the C64 rules. A Z80 program: `.model C128` with a Z80 entry
  runs through the CPU switch block (C128 OQ7, from running the ROM).
- CP/M 3.0 boots from a user-supplied disk (not bundled).
- Harness `test/harness/c128/`; `test/c128-hw/`: MMU (every configuration), CPU switching both ways, Z80
  timing under BA, 2 MHz mode, VDC registers, block copy, ready bit, keyboard, burst; VICE testprogs
  `c128/`, VDC, `z80`, `mmu` (fetched, C128 OQ16); oracle VICE x128.
