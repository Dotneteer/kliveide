fuse &mdash; Sinclair ZX Spectrum emulator
SYNOPSIS
<table width="100%" border=0 rules="none" frame="void"
       cols="2" cellspacing="0" cellpadding="0">
fuse [options]
DESCRIPTION
<table width="100%" border=0 rules="none" frame="void"
       cols="2" cellspacing="0" cellpadding="0">
Fuse is a Sinclair ZX Spectrum emulator. It supports
several models (including the 128), with quite faithful
emulation of the display and sound.
The emulator can load any of the formats supported by
libspectrum(3) &mdash; this includes Z80, SNA and SZX
snapshots, and TAP and TZX virtual-tape files. Saving to
SZX, Z80 and SNA snapshots and TZX and TAP tape files is
supported. The SLT extension to the Z80 format is partly
supported (enough for multi-load games); however, loading of
the old DAT-file variant is not. DSK disk images are
supported when emulating a +3, TRD and SCL disk images are
supported when emulating a Pentagon or Scorpion and DCK
cartridge images are supported when emulating a Timex 2068
variant. Interface II ROM cartridges are also supported.
Finally, there is also support for reading and writing
the RZX input recording format.
See the
COMPRESSED FILES
section for details on reading files compressed with
bzip2(3) or gzip(3).

--aspect-hint
<table width="100%" border=0 rules="none" frame="void"
       cols="2" cellspacing="0" cellpadding="0">
Specify whether the GTK+ and Xlib user interfaces should
&lsquo;hint&rsquo; to the window manager about the preferred
aspect ratio for the graphics window, thus preventing
resizing to non-square sizes which lead to Fuse not
displaying correctly. This option has been observed to cause
problems with some window managers when using the GTK+ UI
which can prevent the window from being resized or moved at
all. (Enabled by default, but you can use
&lsquo;--no-aspect-hint&rsquo;
to disable). See also the
&lsquo;--strict-aspect-hint&rsquo;
option.

-d device
--sound-device device
<table width="100%" border=0 rules="none" frame="void"
       cols="2" cellspacing="0" cellpadding="0">
Specify the sound output device to use and any options to
give that device. If you are not using the SDL UI or using
libao or libasound (ALSA) for sound output,
then the device parameter just specifies the device
to be used for sound output.
If you are using the SDL UI, the device parameter
allows you to specify the audio driver to be used (e.g. dsp,
alsa, dma, esd and arts).
If you are using libao for sound output, the
device parameter allows you to specify the device
used for sound output (either &lsquo;live&rsquo; to a
speaker or to a file) and the parameters to be used for that
device. In general, the device parameter has the form
driver[:param[=value][,param[=value][,...]].
driver selects the libao driver to be used, either
one of the &lsquo;live&rsquo; drivers (aixs,
alsa, alsa09, arts, esd,
irix , macosx, nas, oss or
sun) or a file driver (au, raw,
wav or null). The available parameter and
value pairs for each device are:

THE VARIOUS FRONT-ENDS
<table width="100%" border=0 rules="none" frame="void"
       cols="2" cellspacing="0" cellpadding="0">
Fuse supports various front-ends, or UIs (user
interfaces). The usual one is GTK+-based, but there are also
SDL, Xlib, SVGAlib and framebuffer ones.
The important difference to note is that the GTK+ version
uses &lsquo;native&rsquo; dialog boxes etc. (behaving like a
fairly normal GUI-based program) while the others use an
alternative, Fuse-specific &lsquo;widget UI&rsquo;. This
latter front-end is easily spotted by the way it uses the
main Fuse window/screen for menus and dialogs, and uses the
Spectrum&rsquo;s own font.
MENUS AND KEYS
<table width="100%" border=0 rules="none" frame="void"
       cols="2" cellspacing="0" cellpadding="0">
Since many of the keys available are devoted to emulation
of the Spectrum&rsquo;s keyboard, the primary way of
controlling Fuse itself (rather than the emulated machine)
is via the menus. There are also function key shortcuts for
some menu options.
In the GTK+ version, the menu bar is always visible at
the top of the Fuse window. You can click on a menu name to
pop it up. Alternatively, you can press F1 to display
a pop-up version of the menu bar, which you can then
navigate with the cursor keys or mouse.
In the widget UI pressing F1 is the only way to
get the main menu; and unlike the GTK+ version, the emulator
pauses while the menus are being navigated. The menus show
which key to press for each menu option in brackets.
Pressing Esc exits a menu, and pressing Enter
exits the menu system entirely (as well as
&lsquo;confirming&rsquo; any current dialog).

function key mappings for those items which have them:

Competition mode
<table width="100%" border=0 rules="none" frame="void"
       cols="2" cellspacing="0" cellpadding="0">
Any input recordings which are started when this option
is selected will be made in &lsquo;competition mode&rsquo;.
In essence, this means that Fuse will act just like a real
Spectrum would: you can&rsquo;t load snapshots, pause the
emulation in any way, change the speed or anything that you
couldn&rsquo;t do on the real machine. If any of these
things are attempted, or if the emulated Fuse is running
more than 5% faster or slower than normal Spectrum speed,
then the recording will immediately be stopped.
If libgcrypt was available when Fuse was compiled,
then recordings made with competition mode active will be
digitally signed, in theory to &lsquo;certify&rsquo; that it
was made with the above restrictions in place. However,
this procedure is not secure (and cannot be made so), so the
presence of any signature on an RZX file should not be taken
as providing proof that it was made with competition mode
active. This feature is included in Fuse solely as it
was one of the requirements for Fuse to be used in an
on-line tournament.

DISPLAY SIZE
<table width="100%" border=0 rules="none" frame="void"
       cols="2" cellspacing="0" cellpadding="0">
Some of Fuse&rsquo;s UIs allow resizing of the emulated
Spectrum&rsquo;s display. For the window-based ones (GTK+
and Xlib), you can resize the window by, well, resizing it.
:-) Exactly how this works depends on your window
manager; you may have to make the window over twice the
width and height of the original size before it actually
scales up. Fuse attempts to keep the window
&lsquo;square&rsquo;, but with some window managers this can
mean the window will never resize at all. If you experience
this problem, the
&lsquo;--no-aspect-hint&rsquo;
option may help.
If you&rsquo;re using the SDL UI under X11, the window
will automatically resize to be the correct size for the
graphics filter selected.
GRAPHICS FILTERS
<table width="100%" border=0 rules="none" frame="void"
       cols="2" cellspacing="0" cellpadding="0">
Fuse has the ability to apply essentially arbitrary
filters between building its image of the Spectrum&rsquo;s
screen, and displaying it on the emulating machine&rsquo;s
monitor. These filters can be used to do various forms of
smoothing, emulation of TV scanlines and various other
possibilities. Support for graphics filters varies between
the different user interfaces, but there are two general
classes: the GTK+ and SDL user interfaces (and the saving of
.png screenshots) support &lsquo;interpolating&rsquo;
filters which use a palette larger than the Spectrum&rsquo;s
16 colours, while the Xlib and SVGAlib user interfaces
support only &lsquo;non-interpolating&rsquo; filters. The
framebuffer user interface currently does not support
filters at all.
A further complication arises due to the fact that the
Timex machines have their high-resolution video mode with
twice the horizontal resolution. To deal with this, Fuse
treats these machines as having a &lsquo;normal&rsquo;
display size which is twice the size of a normal
Spectrum&rsquo;s screen, leading to a different set of
filters being available for these machines. Note that any of
the double or triple-sizing filters are available for Timex
machines only when using the SDL user interface.
The available filters, along with their short name used
to select them from the command line, are:
Timex half (smoothed) (half)
Timex half (skipping) (halfskip)

       cols="2" cellspacing="0" cellpadding="0">

down to half normal (Timex) size; that is, the same size as
a normal Spectrum screen. The difference between these two
filters is in how they handle the high-resolution mode: the

which averages pairs of adjacent pixels, while the
&lsquo;skipping&rsquo; version is a non-interpolating filter
which simply drops every other pixel.

continue appending to it. The header needs to have a certain
layout for Fuse to be able to continue appending to it
correctly, and the file will be overwritten if it
can&rsquo;t be appended to.
ZXATASP AND ZXCF
<table width="100%" border=0 rules="none" frame="void"
       cols="2" cellspacing="0" cellpadding="0">
The ZXATASP and ZXCF interfaces are two peripherals
designed by Sami Vehmaa which significantly extend the
capabilities of the Spectrum. More details on both are
available from Sami&rsquo;s homepage,
http://user.tninet.se/~vjz762w/,
but a brief overview is given here.
The real ZXATASP comes with either 128K or 512K of RAM
and the ability to connect an IDE hard disks and a
CompactFlash card, while the ZXCF comes with 128K, 512K or
1024K of RAM and the ability to connect a CompactFlash card.
From an emulation point of view, the two interfaces are
actually very similar as a CompactFlash card is logically
just an IDE hard disk. Currently, Fuse&rsquo;s emulation is
fixed at having 512K of RAM in the ZXATASP and 1024K in the
ZXCF.
To activate the ZXATASP, simply select the ZXATASP
interface option from the Options, Peripherals...
dialog. The state of the upload and write protect jumpers is
then controlled by the ZXATASP upload and ZXATASP
write protect options. Similarly, the ZXCF is controlled
by the ZXCF interface and ZXCF upload options
(the ZXCF write protect is software controlled).
If you&rsquo;re using either the ZXATASP or ZXCF, you
almost certainly want to investigate ResiDOS, the operating
system designed for use with the ZXATASP and ZXCF. ResiDOS
provides facilities for using the extra RAM, accessing the
mass storage devices and a task manager allowing virtually
instant switching between programs on the Spectrum. See
http://www.zxplus3e.plus.com/residos/index.html
for more details.
DIVIDE
<table width="100%" border=0 rules="none" frame="void"
       cols="2" cellspacing="0" cellpadding="0">

http://baze.au.com/divide/.
The interface can be activated via the DivIDE

FILE SELECTION
<table width="100%" border=0 rules="none" frame="void"
       cols="2" cellspacing="0" cellpadding="0">
The way you select a file (whether snapshot or tape file)
depends on which UI you&rsquo;re using. So firstly,
here&rsquo;s how to use the GTK+ file selector.
The selector shows the directories and files in the
current directory in two separate subwindows. If either list
is too big to fit in the window, you can use the scrollbar
to see the rest (by dragging the slider, for example), or
you can use Shift-Tab (to move the keyboard focus to
a subwindow) and use the cursor keys. To change directory,
double-click it.
To choose a file to load you can either double-click it,
or click it then click Ok. Or click Cancel to
abort.
If you&rsquo;re using the keyboard, probably the easiest
way to use the selector is to just ignore it and type in the
name. This isn&rsquo;t as irksome as it sounds, since the
filename input box has filename completion &mdash; type part
of a directory or file name, then press Tab. It
should complete it. If it was a directory, it moves to that
directory; if the completion was ambiguous, it completes as
much as possible, and narrows the filenames shown to those
which match. You should press Enter when you&rsquo;ve
finished typing the filename, or Esc to abort.
Now, if you&rsquo;re using the widget UI &mdash; the one
using the Spectrum font &mdash; the selector works a bit
differently. The files and directories are all listed in a
single two-column-wide window (the directories are shown at
the top, ending in &lsquo;/&rsquo;) &mdash; the names may be
truncated onscreen if they&rsquo;re too long to fit.
To move the cursor, you can either use the cursor keys,
or the Spectrum equivalents
5/6/7/8, or (similarly)
h/j/k/l. For faster movement,
the Page Up, Page Down, Home, and
End keys are supported and do what you&rsquo;d
expect. To select a file or directory, press Enter.
To abort, press Esc.
With both selectors, do bear in mind that all
files are shown, whether Fuse would be able to load them or
not.
MONITOR/DEBUGGER
<table width="100%" border=0 rules="none" frame="void"
       cols="2" cellspacing="0" cellpadding="0">
Firstly, note that the vast majority of this section
applies only if you&rsquo;re using the GTK+ user interface;
if you&rsquo;re using one of the widget user interfaces,
you&rsquo;ll get a very basic monitor which shows the
current values of the registers and allows you to single
step through execution or continue.
If you are using the GTK+ user interface, Fuse features a
moderately powerful, completely transparent
monitor/debugger, which can be activated via the Machine,

top-left &lsquo;pane&rsquo; shows the current state of the

right, the next pane shows where the Spectrum&rsquo;s 64K
memory map (the &lsquo;W?&rsquo; and

writable or contended respectively), and the next a
disassembly, which by default starts at the current program
counter, although this can be modified either by the
&lsquo;disassemble&rsquo; command (see below) or by dragging
the scrollbar next to it. The next pane shows the current
stack, and the final pane any &lsquo;events&rsquo; which are
due to occur and could affect emulation. Any of these panes
can be removed by use of the View menu. Below the
displays are an entry box for debugger commands, and five
buttons for controlling the debugger:

Addresses can be specified in one of two forms: either an
absolute addresses, specified by an integer in the range
0x0000 to 0xFFFF or as a
&lsquo;page:offset&rsquo; combination, which
refers to a location offset bytes into into memory
bank page, independent of where that bank is
currently paged into memory. RAM pages are indicated simply
by an integer, while ROMs are prefixed by
&lsquo;R&rsquo; (e.g. offset 0x1234 in ROM 1 is
specified as &lsquo;R1:0x1234&rsquo;). Pages selected
via the /ROMCS line are prefixed with
&lsquo;C&rsquo;, while the Timex Dock and Exrom use
prefixes &lsquo;D&rsquo; and &lsquo;X&rsquo;
respectively. The 48K machines are treated as having a
permanent mapping of page 5 at 0x4000, page 2 at 0x8000 and
page 0 at 0xC000; the 16K Spectrum is treated as having page
5 at 0x4000 and no page at 0x8000 and 0xC000.
Anywhere the debugger is expecting a numeric value,
except where it expects a breakpoint id, you can instead use
a numeric expression, which uses a restricted version of
C&rsquo;s syntax; exactly the same syntax is used for
conditional breakpoints, with &lsquo;0&rsquo; being false
and any other value being true. In numeric expressions, you
can use integer constants (all calculations is done in
integers), register names (which simply evaluate to the
value of the register), parentheses, the standard four
numeric operations (&lsquo;+&rsquo;, &lsquo;-&rsquo;,
&lsquo;*&rsquo; and &lsquo;/&rsquo;), the (non-)equality
operators &lsquo;==&rsquo; and &lsquo;!=&rsquo;, the
comparison operators &lsquo;&gt;&rsquo;, &lsquo;&lt;&rsquo;,
&lsquo;&gt;=&rsquo; and &lsquo;&lt;=&rsquo;, bitwise and
(&lsquo;&amp;&rsquo;), or (&lsquo;|&rsquo;) and exclusive or
(&lsquo;^&rsquo;) and logical and (&lsquo;&amp;&amp;&rsquo;)
and or (&lsquo;||&rsquo;).
THE POKE FINDER
<table width="100%" border=0 rules="none" frame="void"
       cols="2" cellspacing="0" cellpadding="0">
The &lsquo;poke finder&rsquo; is a tool which is designed
to make the task of finding (infinite lives etc.) pokes for
games a bit easier: it is similar to the
&lsquo;Lifeguard&rsquo; utility which was available for use
with the Multiface. It works by maintaining a list of
locations in which the current number of lives (etc.) may be
stored, and having the ability to remove from that list any
locations which don&rsquo;t contain a specified value.
The poke finder dialog contains an entry box for
specifying the value to be searched for, a count of the
current number of possible locations and, if there are less
than 20 possible locations, a list of the possible locations
(in &lsquo;page:offset&rsquo; format). The five buttons act
as follows:
Incremented
<table width="100%" border=0 rules="none" frame="void"
       cols="2" cellspacing="0" cellpadding="0">
Remove from the list of possible locations all addresses
which have not been incremented since the last
search.
<table width="100%" border=0 rules="none" frame="void"
       cols="2" cellspacing="0" cellpadding="0">
Decremented
<table width="100%" border=0 rules="none" frame="void"
       cols="2" cellspacing="0" cellpadding="0">
Remove from the list of possible locations all addresses
which have not been decremented since the last
search.
<table width="100%" border=0 rules="none" frame="void"
       cols="2" cellspacing="0" cellpadding="0">
Search
<table width="100%" border=0 rules="none" frame="void"
       cols="2" cellspacing="0" cellpadding="0">
Remove from the list of possible locations all addresses
which do not contain the value specified in the
&lsquo;Search for&rsquo; field.
<table width="100%" border=0 rules="none" frame="void"
       cols="2" cellspacing="0" cellpadding="0">
Reset
<table width="100%" border=0 rules="none" frame="void"
       cols="2" cellspacing="0" cellpadding="0">
Reset the poke finder so that all locations are
considered possible.
<table width="100%" border=0 rules="none" frame="void"
       cols="2" cellspacing="0" cellpadding="0">
Close
<table width="100%" border=0 rules="none" frame="void"
       cols="2" cellspacing="0" cellpadding="0">
Close the dialog. Note that this does not reset the
current state of the poke finder.
<table width="100%" border=0 rules="none" frame="void"
       cols="2" cellspacing="0" cellpadding="0">
Double-clicking on an entry in the list of possible
locations will cause a breakpoint to be set to trigger
whenever that location is written to.
An example of how to use this may make things a bit
clearer. We&rsquo;ll use the 128K version of Gryzor. Load
the game, define keys to suit and start playing. Immediately
pause the game and bring up the poke finder dialog. We note
that we currently have 6 lives, so enter &lsquo;6&rsquo;
into the &lsquo;Search for&rsquo; field and click
&lsquo;Search&rsquo;. This reduces the number of possible
locations to around 931 (you may get a slightly different
number depending on exactly when you paused the game). Play
along a bit and then (deliberately) lose a life. Pause the
game again. As we now have 5 lives, replace the
&lsquo;6&rsquo; in the &rsquo;Search for&rsquo; field with a
&lsquo;5&rsquo; and click &lsquo;Search&rsquo; again. This
then reduces the list of possible locations to just one:
page 2, offset 0x00BC. This is the only location in memory
which stored &lsquo;6&rsquo; when we had 6 lives and
&lsquo;5&rsquo; when we had 5 lives, so its pretty likely
that this is where the lives count is stored.
Double-clicking on the &lsquo;2:0x00BC&rsquo; entry in the
dialog will set the appropriate breakpoint (you may wish to
open the debugger at this point to confirm this). Play along
a bit more. When you next lose a life, emulation is stopped
with PC at 0x91CD. Scrolling up a few addresses in the
debugger&rsquo;s disassembly pane shows a value was loaded
from 0x80BC (our hypothetical lives counter), decremented
and then stored again to 0x80BC, which looks very much like
the code to reduce the number of lives. We can now use the
debugger to replace the decrement with a NOP (&lsquo;set
0x91c9 0&rsquo;), and playing the game some more after this
reveals that this has worked and we now have infinite
lives.
THE .DSK FORMAT
<table width="100%" border=0 rules="none" frame="void"
       cols="2" cellspacing="0" cellpadding="0">
In general, disk images for the +3 Spectrum are thought
of as being in DSK format. However, this is actually an
slight oversimplification; there in in fact two
similar, but not identical, DSK formats. (The difference can
be seen by doing &lsquo;head -1 dskfile&rsquo;:
one format will start &lsquo;MV - CPCEMU&rsquo; and
the other will start &lsquo;EXTENDED&rsquo;).
The &lsquo;lib765&rsquo; library used by Fuse to emulate
the +3&rsquo;s FDC supports the &lsquo;CPCEMU&rsquo; format,
but not the extended format. If the &lsquo;libdsk&rsquo;
library was also found while compiling Fuse, this is used to
provide support for the extended format, as well as for
other goodies such as compressed disk images.
TR-DOS DISK FORMATS
<table width="100%" border=0 rules="none" frame="void"
       cols="2" cellspacing="0" cellpadding="0">
Fuse supports .SCL and .TRD images in its Pentagon and
Scorpion emulation; truncated .TRD files need to be expanded
with another utility before use with Fuse.
+D EMULATION
<table width="100%" border=0 rules="none" frame="void"
       cols="2" cellspacing="0" cellpadding="0">
Fuse supports .MGT and .IMG images in its +D emulation.
The +D&rsquo;s printer port is emulated. (See the
PRINTER EMULATION
section for more details.) The +D may only be used with 48K,
128K and +2 (not +2A) emulation. To access disks, load
G+DOS, by inserting a disk containing the DOS file (+SYS)
and entering &quot;RUN&quot;. Once DOS is loaded, you can
load to/from +D disks by prefixing filenames with
&lsquo;dn&rsquo; where &lsquo;n&rsquo; is the
number of the drive in use. For example, &lsquo;LOAD
d1&quot;myfile&quot;&rsquo; would load the file named
&lsquo;myfile&rsquo; from the emulated drive 1. Microdrive
syntax may also be used.
To save a snapshot, choose the &lsquo;Machine, NMI&rsquo;
menu option, and then press &lsquo;4&rsquo; to save a 48K
snapshot, or &lsquo;5&rsquo; to save a 128K snapshot. When
saving a 128K snapshot, you must then press Y or N to
indicate whether the screen changed while saving the
snapshot, to finish saving. You can also choose
&lsquo;3&rsquo; to save a screenshot to disk. Options
&lsquo;1&rsquo; and &lsquo;2&rsquo; allow screenshots to be
printed (in monochrome) if printer emulation is enabled.
COMPRESSED FILES
<table width="100%" border=0 rules="none" frame="void"
       cols="2" cellspacing="0" cellpadding="0">
Assuming the appropriate libraries were available when
libspectrum(3) was compiled, snapshots, tape images,
dock cartridges and input recording files can be read from
files compressed with bzip2(3) or gzip(3) just
as if they were uncompressed. libdsk provides an
equivalent functionality for +3 and +D disk images if
available, but there is currently no support for reading
compressed TR-DOS disk images.
BUGS
<table width="100%" border=0 rules="none" frame="void"
       cols="2" cellspacing="0" cellpadding="0">
Selecting a startup filter doesn&rsquo;t work properly
with user interfaces other than SDL.
Attempting to replay an RZX file without an embedded
snapshot from the command-line doesn&rsquo;t work if you do
&lsquo;./fuse rzxfile snapshot&rsquo;. &lsquo;./fuse
snapshot rzxfile&rsquo; does work though, so use that
instead.
Changing virtual consoles when using SVGAlib for joystick
support causes Fuse to exit. If this is a problem, compile
Fuse with the
&lsquo;--disable-ui-joystick&rsquo;
option.
The poke finder can&rsquo;t search outside
&lsquo;normal&rsquo; RAM.
Using the Options, Joysticks, Joystick 1... or
Options, Joysticks, Joystick 2... options under GTK+
2.x produces a large number of GTK+ critical warnings. This
is a GTK+ bug (#144427), which is fixed in GTK+ 2.4.4.
The libao file output devices not work properly with the
GTK+ UI. No error reporting, but the created file does not
contain any sound data. If you use a &lsquo;weak&rsquo;
machine alsa09 make a lot of click and pop with
&lsquo;ALSA: underrun, at least 0ms.&rsquo; error
messages.
