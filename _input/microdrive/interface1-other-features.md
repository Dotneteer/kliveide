# Interface 1: RS232, ZX Net, and "no drive" behaviour

These are short notes so the plan can decide what to stub. Written in our own words. Tags as in
`sources.md`. Statements derived from reading the ROM's logic are marked **(inferred)**.

---

## 1. RS232 ("t" and "b" channels)

**Hardware.** The serial link is bit-banged by the CPU. The gate array only passes levels through:

- **Send:** port `$F7` write, bit 0, with `$EF` bit 0 (COMMS DATA) = 1 to route `$F7` bit 0 to
  RS232.
- **Receive:** port `$F7` read, bit 7 (TXDATA).
- **Handshake:** CTS is an output on `$EF` write bit 4, DTR an input on `$EF` read bit 3
  [SW], [SM §1.5], [NC].
- The connector is a 9-pin D: 2 TXD (input), 3 RXD (output), 4 DTR (input, high = ready),
  5 CTS (output, high = ready), 7 GND, 9 +9 V pull-up. The names are from the DCE point of view,
  which is why "TX data" is an input [UM App. 4], [SM §1.5.3].
- Levels: about ±12 V, with −12 V generated by a charge pump (it can sag to −7 V) [SM §1.5.2].

**Software** [V2 L0B95–L0D4D]:

- **Baud rate:** `BAUD = 3 500 000 / (26 × baud) − 2` (`$5CC3`). The default is 9600. FORMAT
  "t"/"b" accepts 50–19 200 baud [UM App. 2, App. 6].
- **Send (BCHAN-OUT `$0D07` v2 / `$0C5A` v1):** border = IOBORD. Sets CTS. **Waits for DTR = 1
  (EF bit 3) indefinitely, polling BREAK.** Then `DI` and 11 bit cells (start + 8 data + 2 stop),
  data sent inverted, each cell timed by a 26 T × BAUD loop.
- **Receive (BCHAN-IN):** border = IOBORD. Raises CTS (`$EF`←`$FE`). Polls bit 7 of `$F7` for a
  start bit, needing **4 consecutive reads with bit 7 = 1**, with a time-out of about 800 polls.
  It samples 8 bits at the BAUD interval, then drops CTS. SER_FL holds a one-byte look-ahead.
- **"t" channel:** 7-bit text. Tokens are expanded, codes ≥ `$7F` print as "?", CR becomes CR+LF.
  v2 adds TAB/comma/AT and a line width (`$5CB1`) [GC App. 7].
- The "b" channel sends 8-bit binary unchanged.

**Stub options for Klive:**

- *Disconnected:* return `$F7` bit 7 = 0, so no start bit is ever seen and receive times out with
  "no character". For DTR, either return EF bit 3 = 1, so sends complete into the void, or 0, so
  sends block until BREAK, as with real hardware and nothing plugged in. **(Inferred** from the
  ROM loops.) Fuse offers a `--no-rs232-handshake` option ("assume the other end is live") and
  connects RxD/TxD to FIFOs or files [FUSE].
- *Real:* decode the bit stream from the timing of `$F7` writes (T-state stamps) and present
  received bytes the same way. This is cheap to add later, because the ROM is the UART.

## 2. ZX Net (Sinclair Network)

**Hardware:**

- Two 3.5 mm jack sockets wired in parallel to the gate array's NET pin. A socket with no plug
  inserted terminates the line with 330 Ω, and the two end stations' terminators give about
  165 Ω [SM §1.6].
- Output: `$F7` write bit 0, with `$EF` bit 0 = 0 (network routed). Input: `$F7` read bit 0
  [SW], [NC].
- `$EF` write bit 5 (WAIT) is used for bit synchronisation. The ROM clears it (`$EF`←`$CE`) only
  inside the packet receive loop. [SM §1.4.5] says WAIT "instructs the Spectrum to wait until a
  'looked-for' signal arrives on the network".
- Up to 64 stations (1–64). Station 0 = broadcast [UM ch.7, App. 5].

**Line polarity (inferred** from [V2] CHK-REST, SEND-SC and OUTPAK**):**

- The ROM leaves its output at **1** (released) when idle.
- A **resting** network **reads 0** on `$F7` bit 0.
- While sending the station "scout", the ROM checks after each bit that what it reads back is
  the *inverse* of what it sent. If they match, it assumes a collision and starts again.
- So for a lone station the input is the inverse of its own output, i.e. the line is wired-OR
  and active-low on output.
- A stub that always returns 0 makes the scout loop retry for ever on every 0 bit, and only BREAK
  gets out. A useful stub is `net_in = NOT own_output` (while COMMS DATA = 0), optionally OR-ed
  with remote stations.

**Protocol outline (ROM level)** [V2 L0E09–L10A5], [GC network section], [UM ch.7]:

1. Wait for the line to rest.
2. Send a "scout" containing the own station number (collision-checked bit by bit).
3. Send an 8-byte header (NTDEST, NTSRCE, NTNUMB, NTTYPE, NTLEN, NTDCS, NTCHS).
4. Wait for a 1-byte response.
5. Send up to 255 data bytes, then wait for a response.
6. Type 1 marks the EOF packet.

The "n" channel is 276 bytes with a 255-byte buffer [UM App. 3]. Bits are paced by tight CPU
loops, so emulation needs cycle-accurate timing of `$F7` accesses. Fuse does not emulate the
Sinclair Network, at least for DISCiPLE, and says so [FUSE]. OqtaDrive bridges it to the Internet
in hardware [OQ network.md].

**Recommendation:** stub it. Give inverse loopback so that the ROM's network commands fail
cleanly or time out instead of hanging. Keep the bit-level design open for a later "OqtaNet-style"
bridge.

## 3. Behaviour with no drive, no cartridge, or a bad cartridge

| Situation | What the hardware shows | What the ROM reports |
|---|---|---|
| Drive number with no drive attached, or drive with no cartridge | the select bit shifts out into nothing; EF bit 2 (GAP) stays 1, bit 0 (WP) = 0 | SEL-DRIVE: after the ~37 ms delay and ~5000 failed presence tests (~0.15–0.2 s) → **"Microdrive not present"** (code `$10`). All motors off, interrupts back on [GC 17F7–1829], [UM App. 5] |
| Unformatted (blank or erased) cartridge | all gap, GAP = 1 | "Microdrive not present" [UM App. 5] |
| FORMAT on an empty drive | FORMAT skips the presence test. WP reads 0 | **"Drive 'write' protected"** (inferred from [GC 1B74–1B85] and [SM §2.7]) |
| Write-protected cartridge (tab removed) | WP = 0 | "Drive 'write' protected" (`$0E`) on SAVE, OPEN for write, ERASE, FORMAT |
| Name not found / record missing | — | "File not found" (`$11`) after ~5 revolutions (GET-RECD, 1275 sectors) |
| Cartridge full | map all set | "Microdrive full" (`$0F`). An unclosed file left behind must be ERASEd [UM App. 5] |
| Cartridge pulled during a read (motor running, no signal) | GAP = 1 for ever | v1: loops in GET-M-HD until BREAK. v2: header search times out after 65 536 gap-loop iterations, then ROM retry logic → typically "File not found" (inferred from [V2 L15DE]) |
| `IN` from port `$E7` (or any port with A4 = A3 = 0) outside the ROM's protocol | /WAIT held until 8 bits arrive | Machine hangs: the "IN 0 crash" [IO], [NC] |
| BREAK (CAPS+SPACE) during any wait loop | — | "BREAK into program" (main report L). Temporary channels reclaimed, motors off (RCL-T-CH). Breaking while a write channel is closing can leave an unclosed file [GC 17B9, 1785 note], [UM App. 2] |
| BREAK while an autorun program loads from microdrive | — | the ROM **resets the machine** (jumps to main-ROM `$0000`) [GC 0040–0060] |
